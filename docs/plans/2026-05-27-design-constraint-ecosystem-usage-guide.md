# Design Constraint 生态 5 技能使用指南

> **目标:** 让任何 agent 进入新项目后，知道如何按正确顺序调用 5 个技能完成评审/分析/修复。

**架构:** `nav`(文档导航) → `dc`(检测入口) → `ddr`(文档评审) / `cda`(代码分析) → `td`(任务拆分)

---

## 一、5 技能定位与触发

| 优先级 | 技能 | 一句话 | 什么时候用 |
|--------|------|--------|-----------|
| P51 | `docs-navigator` | 入口导航 | 进入新项目，文档>10 个，需要了解项目 |
| P52 | `design-constraint` | 检测入口 | "评审 xxx"、"检查完整性" |
| P53 | `design-doc-reviewer` | 文档评审 | "评审文档"、"文档不够深入" |
| P54 | `code-design-analyzer` | 代码分析 | "分析代码"、"对比实现与设计" |
| P55 | `task-decomposer` | 任务拆分 | "拆分任务"、"生成执行计划" |

**触发矩阵：**

| 用户说 | 触发链 | 说明 |
|--------|--------|------|
| "评审 xxx" | dc → nav Step0 → 自适应检查 | 主流程 |
| "评审 xxx 文档" | dc → nav → ddr | 文档评审 |
| "评审 xxx 代码" | dc → nav → cda | 代码分析 |
| "评审 xxx 模块" | dc → nav → ddr + cda 并行 | 全量审查 |
| "了解项目" | nav → 阅读路径 | 导航 |
| "拆分任务" | td | 直接拆分 |
| "修复文档" | ddr → td | 文档补全→拆分 |
| "修复代码" | cda → td | 代码修复→拆分 |
| "复查" | dc → git diff | 增量验证 |

## 三、每个技能的详细使用方式

### 3.1 docs-navigator (P51) — 文档导航

**输入：** 项目路径
**输出：** 文档结构快照 + INDEX.md + 阅读路径

**6 大能力：**

| 能力 | 说明 | 输出 |
|------|------|------|
| 索引生成 | 扫描 docs/ → INDEX.md | INDEX.md（含优先级+依赖） |
| 知识定位 | 按主题定位文档 | "架构文档在 docs/architecture/" |
| 阅读规划 | 按目标生成阅读路径 | "了解CI/CD → 读这3篇" |
| 冲突检测 | INDEX vs 目录一致性 | "3个新文档未收录" |
| 🧪 过时检测 | 文档 mtime < 代码 mtime | "gateway-routing.md → 代码70天前修改过" |
| 📝 系统全景 | 从代码生成文档 | 架构文档/API文档/模块README |

**设计系统文档生成：**
```
/docs-navigator:generate-design-system
  → 从 src/tokens/ → Design Token 表（color/spacing/radius/shadows/typography）
  → 从 src/components/ → 组件库文档（Props/状态/Token使用）
  → 从 src/microfront/ → 微前端契约（Channel/生命周期/认证传播）
```

### 3.2 design-constraint (P52) — 检测入口

**输入：** 项目路径 + 评审目标
**输出：** 自适应检查报告 + Score/100 + P0/P1 缺陷清单

**5 Step 流程：**
```
Step 0: 文档导航 (docs-navigator) ← 前置必做
Step 1: 项目类型探测 → 8种之一
Step 2: 文件存在性检测 → 有CI?有文档?有k8s?
Step 3: 按类型执行检查 → agent→Q1-Q7, frontend→W1-W8
Step 4: 智能分发 → ddr(文档)/cda(代码)/td(拆分)
```

**项目类型 → 维度映射：**

| 类型 | 维度 | 不检查什么 |
|------|------|-----------|
| agent-framework | Q1-Q7 | W1-W8 (Web维度) |
| frontend-spa | W1-W8 | C1-C8 大部分 |
| cli-tool | W1/W5/W7, Q6 | W2/W4/W8 (UI) |
| backend-api | W1/W5/C/S | W2/W4 (交互) |
| fullstack | 全维度 | — |

**CI/CD 关键修正：** 有 .github/workflows/ 才检 CI 配置，没有 → C7=N/A，不报错。

### 3.3 design-doc-reviewer (P53) — 文档评审

**输入：** 文档路径 + projectType
**输出：** 评审报告 + P0/P1 缺陷 + 交互细节补全

**8 个能力：**
1. 操作链路完整性（6环节/100%）
2. 页面交互串联（4维度/100%）
3. 跨系统串联（5检查项/100%）
4. 产品用户视角（用户故事/功能拆分/操作流程）
5. 开发者视角（前端规范/后端规范/开发体验）
6. 大厂模式对标（8大厂知识库）
7. 交互细节生成（缺失功能自动补全：布局+交互链+Token+五态+空状态）
8. 大型系统全栈评审（8技术栈19维度/100%）

**场景逆向验证模板：**
从用户视角和开发者视角各走一遍操作链，验证文档是否覆盖完整。

**协同规范：**
```
评审文档 → 发现需要代码分析 → 调用 cda
评审文档 → 需要拆分任务 → 调用 td
```

### 3.4 code-design-analyzer (P54) — 代码分析

**输入：** 代码路径 + 可选设计文档路径 + projectType
**输出：** 代码分析报告 + 架构评分 + 对比报告 + 修复方案

**8 个能力：**
1. 代码架构深度分析（7维度：架构/模式/依赖/边界/租户/错误/日志）
2. 文档与代码对比（一致/缺失/不一致三清单）
3. 代码级设计评审（API/错误码/日志/安全/性能）
4. 前端交互链代码分析（7维度评分：入口/loading/CRUD/校验/空状态/Token/状态）
5. 大型系统全栈代码分析（11技术栈/代码实现率%）
6. 大厂模式适配（瓶颈→匹配→适配→生成方案）
7. 设计增强方案（增强点清单+实施顺序+兼容性）
8. 系统级瓶颈诊断与设计意图分析（技术债+演进路径+组件补全+Token替换映射）

**评分公式：** 代码实现率 = 已实现维度数 / 11 * 100%

**协同规范：**
```
分析代码 → 发现文档缺失 → 调用 ddr
分析代码 → 需要拆分实现任务 → 调用 td
```

### 3.5 task-decomposer (P55) — 任务拆分

**输入：** 目标文档路径 + 评审缺失项清单
**输出：** 子任务拆分表 + 依赖DAG + 执行计划 + 验证用例

**7 个能力：**
1. 功能拆分到子任务（含交互链8项验证）
2. 用户操作流程设计（详细步骤模板）
3. 交互逻辑深度分析（逐元素交互链审查）
4. Spec 驱动执行（验收标准 + agent 配置 + 质量门控）
5. 大型系统按技术栈分层拆分（8层跨层依赖分析）
6. 功能验证用例生成（V-001~V-010模板）
7. 组件级交互规格生成（布局+交互链+五态+Token清单）

**交互链验证（8项强制检查）：**
```
1. 操作入口 ✅  2. 用户反馈 ✅  3. 加载状态 ✅  4. 空状态 ✅
5. CRUD完整 ✅  6. 表单校验 ✅  7. 错误处理 ✅  8. 保存入口 ✅
任一不通过 → 子任务标记"交互缺失"，必须补充
```

**质量门控（拆分时强制）：**
- 无"只读无编辑"
- 无"无保存入口"
- 无"静默失败"
- 无"硬编码色值"（标注必须使用的 Design Token）

## 五、典型用例

### 用例1: "评审 orion-design 项目"

```
用户: "评审 orion-design"
  → nav: scan docs/ → 156文档, 42子目录 → P0:12篇, P1:45篇
  → agent 读 P0 文档 (架构总览/微服务地图/ADR-002/Design-Tokens)
  → dc: 探测类型 → fullstack (monorepo 50+微服务+SPA)
  → dc: CI/CD FOUND (3 workflows) → C7启用
  → dc: k8s FOUND (2 templates) → 检查 securityContext
  → ddr: 评审设计文档 → 7/8 维度评分
  → cda: 分析代码实现 → 前端交互链 + 全栈代码分析
  → dc 整合报告 → Score 68/100 + 8 P0 + 12 P1
  → 用户: "修复"
  → td: 拆分 P0 修复为子任务 (含交互链验证)
  → 输出: 子任务表 + 执行计划 + 验证用例
```

### 用例2: "了解新项目"

```
用户: "了解 xxx 项目"
  → nav: scan docs/ → 文档结构快照
  → 生成 INDEX.md (P0/P1/P2 优先级)
  → 阅读路径: "想了解CI/CD → 读这3篇"
  → 检测过时文档: "5篇文档落后代码变更"
```

### 用例3: "只检查 CI/CD"

```
用户: "检查 CI/CD"
  → dc: 探测类型 → 任何类型
  → dc: CI/CD 文件存在性检测
  → 只检 C7/C8/S3 维度 (跳过 A1-A3/B1-B2/D1-D5)
  → 输出: CI/CD 检查报告
```

### 用例4: "生成设计系统文档"

```
用户: "生成设计系统文档"
  → nav: generate-design-system
  → 从 src/tokens/ → colors/spacing/radius/shadows/typography 表
  → 从 src/components/ → 组件库文档 (Props/状态/Token)
  → 从 src/microfront/ → 微前端契约文档
  → 输出到 docs/design-system/
```
